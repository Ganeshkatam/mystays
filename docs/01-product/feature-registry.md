# Feature Registry

Every feature receives a stable MY-NNN identifier.

## Statuses
- Proposed
- Planned
- In Progress
- Released
- Deferred
- Rejected
- Superseded

## Registry rules
- Never silently delete a feature.
- Record scope changes in the feature's history.
- Link architectural decisions to ADRs.
- Keep implementation and specification synchronized.

## Current priority model
- P0: required for the current phase.
- P1: important after core validation.
- P2: strategic/future.

Detailed feature definitions should be added here as each feature enters active delivery.
